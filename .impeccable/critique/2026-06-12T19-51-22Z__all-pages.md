### Anti-Patterns Verdict

**LLM assessment**: The codebase avoids the most obvious AI-slop tells: no gradient text, no glassmorphism as default, no numbered section markers, no ubiquitous uppercase eyebrows. The slop that *is* present is subtler and more systemic:

- **`border-border/50` pattern** — appears on 9+ pages, lowering contrast and making interactive elements visually indistinct from non-interactive ones. This is the 2024-25 shadcn monoculture tell.
- **Gradient avatar circles** (`bg-gradient-to-br from-primary/20 to-primary/10`) — repeated on Create, Community, Profile pages. A signature AI-generated pattern for placeholder visuals.
- **Identical card grids** — Scenario detail's 3-column related grid, Analytics' 4-column stat grid, ReplayHeader's 4-column info grid. Same pattern at different densities.
- **SaaS pricing template** — 3-card grid with "Populaire" floating badge on the middle tier. Indistinguishable from 10,000 other pricing pages.

**Deterministic scan**: `detect.mjs` returned `[]` across all 23 page files — zero pattern matches. The detector's rule set doesn't catch these systemic design monoculture issues.

---

### Overall Impression

This is a **solid B-** codebase with significant production-readiness gaps. The design system is coherent (shadcn/ui + Tailwind + CSS variables, consistent dark mode, shared component library), but:

1. **The brand personality promised by the landing page ("AI Social Chaos") is not delivered by the rest of the product.** The explore page is a sterile 50-item grid with 9 filter pills. The dashboard is a generic metric screen. The gap between promise and delivery is the single biggest UX issue.

2. **Three pages are production placeholders**: Admin Analytics (all stats `"—"`), Profile (construction icon), and the three legal pages (zero navigation — orphaned).

3. **The architecture is split** between tRPC (marketing/dashboard) and raw fetch (auth pages), meaning error handling and loading patterns are inconsistent.

4. **Accessibility is uneven** — good ARIA in auth pages (login/register), critical violations in Community (`<Link>` wrapping interactive children), missing labels across admin pages.

---

### What's Working

1. **Shared component patterns**: `DataLoader`/`PaginatedDataLoader` provide consistent loading/error/empty states across most pages. `DashboardShell` wraps 7/9 dashboard pages with consistent navigation. `EmptyState` is used uniformly.

2. **Client-side polish on the landing page**: `LiveCallPreview`, community proof strip, audio visualizer, staggered animations — this page shows what the team can do when they aim for personality.

3. **Error handling basics**: Auth forms have `aria-describedby` for errors, mutations use `useApiToast`, `DataLoader` has retry. The infrastructure for good UX exists.

4. **French localization**: The entire UI is in natural French with appropriate Gen Z/tone — no translation artifacts or mechanical language.

#### 🔴 P1 — Password gate blocks conversions on Register
**File**: `(auth)/register/page.tsx:169`
**What**: Submit button disabled until `passwordStrength < 4` (all 5 criteria must pass: 8+ chars AND 12+ chars AND uppercase AND digit AND special char). For a casual TikTok-oriented app.

**Suggested**: `/impeccable distill register`

#### 🔴 P1 — Community card wraps interactive children in `<Link>`
**File**: `(dashboard)/community/CommunityPageClient.tsx:63`
**What**: An entire card is a `<Link>` containing interactive children (`ReactionBar`, comment `Input`, `Button`). Invalid HTML, breaks screen readers, causes fat-finger issues.
**Fix**: Restructure so only the card title/body is the link, not the full card.
**Suggested**: `/impeccable harden community`
